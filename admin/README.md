# Vitaly Krauss Studio

Закрытая студия цифрового художника: вход владельца, библиотека работ, серии, выставки, размеры и цены принтов, публикация каталога и управление доступом.

Публичный сайт остаётся на GitHub Pages. Содержимое `admin/` не входит в публикуемый архив Pages. Для студии нужен отдельный постоянно работающий процесс Node.js и постоянный диск для SQLite.

## Публичные тексты и загрузка каталога

`js/i18n.js` — единый словарь EN/RU/ES для публичного интерфейса и ошибок корзины. В публичном JavaScript и HTML нет встроенного старого каталога или биографии. Имя, роль, вступление, биография и почта приходят из опубликованного About; они же определяют имя на главной, title/meta, подписи бренда и тему ответа из студии. Изначальные тексты в `admin/src/about.mjs` и работы в `admin/seed` нужны только для первичного наполнения, а не для подмены сохранённых данных.

До загрузки показывается состояние ожидания; при первом сбое — переведённая ошибка с повтором. Если реальный каталог уже был получен в этой вкладке, ошибка фонового обновления оставляет его на экране с уведомлением. Демонстрационные работы и цены не появляются. Пустые сохранённые поля автора остаются пустыми. Метаданные обновляются клиентом после ответа API.

## Корзина, запросы и информация об авторе

Корзина доступна на обеих публичных страницах: количество, миниатюры, размеры, цены, количество экземпляров и удаление. Выбор и настройки языка/темы/cm–in сохраняются в localStorage. Отправка требует только почту; имя и комментарий необязательны. Корзина очищается только после успешного ответа сервера. Стабильный ID предотвращает дубли при повторе после сбоя. Цена и доступность проверяются по опубликованному каталогу, изменение цены требует пересмотра выбора.

`POST /api/requests` принимает только разрешённый Origin, до 32 КБ JSON, до 50 вариантов и 99 экземпляров. Лимиты в SQLite: 5 запросов за 10 минут для хешированного IP и 200 в сутки всего. IP не сохраняется в открытом виде. Ответ не содержит персональных данных. Inbox `/api/studio/requests` и изменение прочтения/обработки доступны только вошедшему владельцу. Последние 500 запросов показываются в студии; записи остаются в SQLite и резервной копии. Колокольчик обновляется при входе и каждые 30 секунд. Сохраняются почта, выбранные работы/серии/места выставок, точные физические размеры, цена и количество на момент запроса. Отсутствие SMTP не мешает получению запроса в студии.

Раздел **Обо мне** редактирует EN/RU/ES имя, роль, вступление, биографию и контактную почту. Фото загружается с устройства, кадр выбирается в Cropper.js, круглое превью показывает результат. На сервер отправляется оптимизированная квадратная WebP 600×600; исходное фото автора не публикуется. Черновик и публикация разделены как у каталога. По умолчанию используется предоставленный портрет. После замены требуется публикация.

Работы в серии, работы выставки и медиаматериалы переставляются за изображение или ручку, включая сенсорное перетаскивание; доступны также кнопки вверх/вниз. Первое изображение определяет обложку. Порядок сохраняется с черновиком/публикацией. Для серии порядок хранится отдельно в `series[].workIds`, поэтому перестановка не меняет другие серии или выставки. SortableJS 1.15.7 и Cropper.js 2.3.1 закреплены в package-lock; локальные browser bundles и MIT-тексты находятся в public/. При обновлении зависимости нужно обновить соответствующий bundle и лицензию.

## Управление каталогом

Сохранение, публикация, загрузка, удаление и операции доступа показывают заметные тосты: выполнение, успешный ответ сервера или ошибка. Успех закрывается через 6,5 секунды (таймер приостанавливается при наведении/фокусе), ошибки закрываются вручную. Тост виден поверх открытой модалки.

- **Работы:** нажмите «Добавить работу» в каталоге, серии или выставке. Откроется единая модалка: перетащите несколько изображений или выберите файлы кликом. Сразу отображаются локальное превью и ход загрузки, затем — поля редактирования. Для каждой работы требуется название хотя бы на одном языке; описание, год и серия необязательны. Можно заменить изображение, загрузив оригинал вместо имеющейся веб-копии.
- **Размеры:** для нового оригинала максимальный формат рассчитывается по пикселям и DPI файла. Если плотность не указана, используется 300 DPI. DPI можно изменить; существующие форматы пересчитываются только по явному действию владельца. Название новой работы — имя файла без расширения, включая дефисы и подчёркивания. Максимальный размер становится первой строкой; остальные размеры должны быть меньше. Цена в евро необязательна и задаётся для каждого размера отдельно. Нет остатков и статусов продажи: это печать по запросу.
- **Магазин:** работа появляется автоматически, если хотя бы у одного размера указана положительная цена. Варианты без цены не предлагаются для покупки. На карточке показываются серия и места всех связанных опубликованных выставок.
- **Главная:** тумблер «Работа на главной» выбирает заглавное изображение. При замене отображается подтверждение с названиями старой и новой работы. После выбора нажмите «Опубликовать»; предварительно сохранять черновик не требуется.
- **Серии:** отдельный список `/series` и редактор `/series/:id/edit`, как у выставок. Название, описание, соавтор по желанию. «Добавить из загруженных» открывает выбор существующих работ; перенос из другой серии требует подтверждения. «Убрать» сохраняет работу в библиотеке без серии. Архивирование/восстановление сразу меняет видимость серии, не публикуя остальные черновые правки.
- **Редактирование выставок:** вкладка `/exhibitions` показывает только список и действия. «Редактировать» открывает отдельную страницу `/exhibitions/:id/edit`; поддерживаются прямой адрес, обновление и история браузера. В «Работах выставки» только прикреплённые работы: «Убрать» снимает связь, сохраняя саму работу. Полный каталог открывается отдельно кнопкой «Добавить из загруженных» с подтверждением выбора. Архивирование/восстановление выставки сразу сохраняет её видимость на сайте, остальные черновые изменения не публикуются.
- **Выставки:** название, описание, даты или известный год, площадка, город, необязательная ссылка на внешний сайт. Отдельный блок фотографий поддерживает выбор нескольких файлов и drag-and-drop, оптимизированные превью, удаление фотографии из выставки. Фотографии не создают работы каталога. Публичная карточка ведёт на отдельную страницу exhibition.html?id=… с подробностями, работами и затем медиаматериалами. Обложка — первая выбранная работа; без выбранных работ используется первая фотография. Полные даты отображаются как 10 Feb 2026, известный только год остаётся годом. Работы можно отметить из библиотеки или загрузить прямо в выставку. Новые изображения редактируются в той же модалке и сразу привязываются к выставке. Название предварительно заполняется именем файла, его можно изменить. Одна работа может участвовать в нескольких выставках.
- **Архив:** работы, серии и выставки можно архивировать и восстанавливать. Архив не удаляет оригиналы. Архивированная выставка не скрывает саму работу. Архивированная серия скрывает группировку; её активные работы остаются доступны отдельно. Для заглавной работы требуется подтверждение снятия с главной.
- **Окончательное удаление:** доступно только для архивированной работы, серии или выставки, по кнопке «Удалить навсегда» с подтверждением по названию. Удаление сразу применяется к черновику и опубликованному каталогу, остальные правки остаются только в черновике. Удаление работы очищает её связи с выставками и главной; неиспользуемые оригинал и превью удаляются с диска. Общие с другой работой изображения сохраняются. При удалении серии её работы остаются без серии; удаление выставки не удаляет работы. Восстановления из интерфейса нет.
- **Языки:** EN/RU/ES. Английский первым и раскрыт по умолчанию в редакторе; публичный сайт впервые открывается на английском, затем сохраняет выбранный посетителем язык. При отсутствии перевода отображается заполненный текст другого языка. Автоперевода нет.

«Сохранить черновик» сохраняет изменения только в студии. «Опубликовать» одним запросом сохраняет текущие изменения и публикует каталог. Черновик можно сохранить с незаполненными названиями и датой выставки для продолжения позже; перед публикацией обязательные поля проверяются. При ошибке или конфликте вкладок правки остаются в текущем окне, прежняя публикация не перезаписывается. Публичный сайт получает каталог при открытии, возвращении во вкладку и каждые 30 секунд в активной вкладке. Рядом с размерами принта в магазине и окне работы доступен запоминаемый выбор cm/in; размеры отображаются целыми, точные пропорции сохраняются для печатных файлов.

При первом запуске автоматически импортируются прежние десять работ, две серии и три выставки. Этот импорт выполняется только при отсутствии каталога в базе, не перезаписывая последующие изменения. У старых выставок сохранён только известный год; связи с работами следует указать вручную. Старые цены и физические размеры были демонстрационными; цены сохранены, пропорции приведены к изображениям.

### Изображения и файлы для печати

Оригиналы хранятся только в приватном томе. Для сайта создаются WebP-копии не более 1400 px по длинной стороне и миниатюры 280 px, без встроенных метаданных. Публично доступны только производные изображения активных опубликованных работ; черновики и оригиналы требуют входа. Архивирование и публикация отзывают доступ к веб-копиям, но уже скачанные посетителем изображения технически отозвать невозможно. Это ограничивает качество копии для печати, а не является DRM.

В студии можно скачать исходный оригинал или файл для выбранного размера: JPEG высокого качества, с выбранным DPI работы (по умолчанию 300) без увеличения исходных пикселей и без нарушения пропорций. Если разрешения оригинала недостаточно для заданных сантиметров при выбранном DPI, итоговая плотность будет ниже. Для старых работ пока доступны только прежние веб-копии: сначала загрузите настоящие оригиналы, чтобы получить файлы для печати.

Изображения обрабатываются последовательно, включая печатные экспорты. Допустимы статичные JPEG, PNG, WebP, AVIF и TIFF, до 100 МБ и 100 Мп. SVG и анимация не принимаются. Перед загрузкой проверяется свободное место: приложение сохраняет резерв минимум около 1 ГБ для остальных сервисов VPS.

## Локальный запуск

Node.js 22.13 или новее. В Node 22 встроенная SQLite выводит предупреждение об экспериментальном API; тесты проверяются на установленной Node 22.20. Зависимости закреплены в lock-файле.

В терминале из папки `admin`:

```powershell
npm ci
npm run setup
npm run build
npm start
```

`setup` создаст локальный `.env` со случайным секретом и попросит дважды ввести пароль владельца. Ввод скрыт. Пароль не выводится и не сохраняется в `.env`; в базе хранится его хеш Better Auth. Владелец по умолчанию: `kraussvitaliy@gmail.com`.

Откройте `http://localhost:4174`. Используйте именно этот адрес, а не `127.0.0.1`: проверяется канонический Host, а passkeys привязаны к домену.

После входа по паролю можно добавить passkey и далее входить с отпечатком, Face ID, Windows Hello или ключом безопасности. Совместимость конкретного устройства зависит от его браузера и системы. Публичная регистрация отсутствует и запрещена на сервере.

`.env`, `.data/`, базы и собранный клиент исключены из Git. Не запускайте публичный файловый сервер из корня репозитория: студия сама отдаёт только перечисленные файлы интерфейса.

## Восстановление доступа

С доступом к терминалу сервера:

```powershell
npm run setup -- --reset
```

Команда заменяет пароль настроенного владельца, завершает все его сеансы и удаляет все прежние passkeys. Ключи потребуется добавить заново. Это восстановление учётной записи, а не обычная смена пароля. Обычная смена пароля в интерфейсе оставляет текущий сеанс и passkeys, но завершает другие сеансы.

Нет публичной ссылки «Забыли пароль», SMTP или обходного HTTP-адреса первоначальной настройки. Создание владельца выполняется только локальной командой с доступом к приватной базе.

## Публикация

До запуска снаружи необходимо выбрать хостинг и постоянный адрес, например `https://studio.vitalykrauss.art`. DNS пока не изменялся.

1. Установить зависимости (`npm ci`) и собрать клиент (`npm run build`).
2. Создать приватный `.env`, пользуясь `.env.example`. Указать `BETTER_AUTH_URL` с окончательным HTTPS-адресом, `OWNER_EMAIL`, новый случайный `BETTER_AUTH_SECRET` и `NODE_ENV=production`.
3. Указать `AUTH_DATABASE_PATH` на постоянном приватном диске. Обеспечить доступ только пользователю процесса и настроить резервные копии SQLite. Папка базы не должна обслуживаться веб-сервером. На Windows доступ ограничивается ACL; Unix mode сам по себе ACL Windows не заменяет.
4. Выполнить `npm run setup` на сервере для создания владельца. Команда не перезаписывает существующий `.env`. Не использовать тестовую базу или тестовые пароли.
5. Настроить HTTPS-прокси, сохраняющий исходный `Host`. По умолчанию процесс слушает только `127.0.0.1:4174`. `HOST=0.0.0.0` нужен только для контролируемой контейнерной сети или аналогичного размещения.
6. Если используется прокси, задать `TRUST_PROXY_IPS` его точными IP-адресами. Прокси должен перезаписывать `X-Forwarded-For`, а прямой доступ к процессу должен быть закрыт. Не задавать доверие ко всем адресам. Для локального nginx это обычно `127.0.0.1,::1`. Без этой настройки доверяется только IP сокета, заголовки клиента игнорируются.
7. Запустить `npm start` под менеджером процессов, проверить вход, выход, passkey и резервное восстановление на окончательном домене. Не копировать локальные passkeys: они привязаны к домену.

Изменение `BETTER_AUTH_SECRET` завершает действующие входы. Изменение домена потребует повторной настройки ключей. Вход без TLS разрешён исключительно для локальной разработки; конфигурация production требует HTTPS.

## VPS с уже установленными сервисами

В `Dockerfile` и `compose.yaml` подготовлен отдельный контейнер. Он не занимает порты 80/443, не использует Docker socket, не меняет соседние контейнеры и хранит базу в собственном именованном томе. Привязка по умолчанию — только `127.0.0.1:4174` на хосте. Если порт уже занят, задайте свободный `STUDIO_BIND_PORT` в `.env`. Не запускайте второй экземпляр с тем же именем Compose-проекта, если он уже используется на этом сервере.

После проверки существующих портов, Docker-проектов и HTTPS-прокси:

1. Поместить `admin/` в отдельную папку, например `/opt/vitalykrauss-studio`.
2. Создать `.env` из `.env.example`. Указать окончательный HTTPS-домен, владельца, production и случайный секрет. Секрет можно получить локально командой `openssl rand -base64 48`; не пересылать его в чат и не добавлять в Git. Ограничить права файла: `chmod 600 .env`.
3. Выполнить `docker compose build`.
4. Создать владельца: `docker compose run --rm --no-deps studio npm run setup`. При полном окружении команда ничего не пишет в корень контейнера; сохраняет только хеш в приватном томе. Пароль запрашивается в терминале.
5. Выполнить `docker compose up -d`.
6. Добавить новый поддомен в существующий прокси, направив его на выбранный локальный порт. Не устанавливать второй nginx/Caddy поверх существующего и не заменять его общую конфигурацию.

Для nginx на хосте в новом HTTPS-виртуальном хосте потребуются, в частности:

```nginx
location / {
    proxy_pass http://127.0.0.1:4174;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto https;
    client_max_body_size 105m;
}
```

Сертификат и виртуальный хост подключаются средствами уже установленного прокси/панели. Если и прокси находится в Docker, сетевое подключение адаптируется к его существующей сети вместо публикации порта наружу. Точный `TRUST_PROXY_IPS` берётся из фактической сетевой конфигурации: при Docker это адрес прокси/шлюза, видимый контейнеру, а не обязательно `127.0.0.1`. Проверить разделение лимитов для двух внешних клиентов.

Не выполнять `docker compose down -v`: это удаляет том с владельцем, сессиями и passkeys. Для восстановления доступа использовать `docker compose run --rm --no-deps studio npm run setup -- --reset`. Контейнер работает без root и с файловой системой только для чтения; writable остаются приватный том и временная папка.

Docker-сборка и размещение проверены на VPS: контейнер работает без root, с файловой системой только для чтения и без опубликованных портов. Для существующего Docker-прокси используется `compose.vps.yaml` вместе с `compose.yaml`. Перед применением на другом сервере нужно создать отдельную сеть, подключить к ней прокси и указать его доверенный IP.

Лимиты входа хранятся в базе и разделяются по адресу клиента. Для внешнего сервера также нужны лимиты запросов и ограничение размера тела на HTTPS-прокси. Для студии на Caddy установлен отдельный лимит 105 МБ, приложение принимает один файл до 100 МБ и 100 Мп. SQLite рассчитана здесь на один процесс студии с постоянным диском, а не на независимые serverless-инстансы.

## Границы доступа

- Срок сеанса — 8 часов; изменение срока не кэшируется в клиентском токене. Чувствительные операции passkey требуют свежего входа по правилам Better Auth.
- Каждый приватный запрос повторно проверяет сессию и адрес подтверждённого владельца. Вход другого пользователя не создаёт сессию даже при наличии его записи в базе.
- Для запросов изменения обязателен точный Origin. Список доступных HTTP-методов и маршрутов авторизации ограничен сервером.
- Секреты, owner allowlist, хеши, сырые токены сессий и серверные ошибки не встраиваются в клиент. Доступен только минимальный профиль уже вошедшего владельца.
- Cookie: HttpOnly, SameSite=Lax, Secure для HTTPS, без передачи между поддоменами. Интерфейс запрещает встраивание и кэширование, отмечен noindex. Это дополнения к авторизации, а не замена ей.
- Исходящих писем и доступа к Gmail нет. Публичная корзина отправляет запрос в приватный inbox студии; владелец отвечает кнопкой открытия своего почтового приложения.

## Проверки

```powershell
npm test
npm run check
npm run build
npm audit --omit=dev
```

Интеграционные тесты используют отдельные временные базы, реальные HTTP-запросы и Better Auth. Проверяются закрытая регистрация, владелец, сессии/выход/истечение, Origin/Host, Secure-cookie, лимиты и подделка IP-заголовков, защита passkey и файлов, восстановление.

Браузерная проверка в Edge с Playwright: 320/375/768/1440 px, ошибка пароля, вход и выход, регистрация виртуального WebAuthn-ключа, вход этим ключом, смена пароля и удаление ключа. На production проверены действительный HTTPS-сертификат, экран входа на desktop/mobile, вход и выход владельца, запрет чужого Origin и недоступность закрытых файлов. Владелец создан на сервере; начальный пароль хранится только в приватном root-файле. Физические Face ID/Windows Hello и Safari/Firefox не проверялись. Тестовые локальные учётные записи и базы удаляются после проверки.
