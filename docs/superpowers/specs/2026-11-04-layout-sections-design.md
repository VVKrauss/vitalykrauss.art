# Настраиваемые секции сайта, независимый хедер, Works + Contact

## Зачем

Сейчас порядок и состав секций публичного сайта (`Works`/Series, `Exhibitions`, `Shop`, `About`) жёстко прошит в `index.html`. Владелец хочет управлять составом главной страницы из студии: включать/выключать блоки и менять их порядок, не трогая код. Отдельно — упростить и выделить хедер (сейчас это просто текст из About), объединить Series с Works (превратив серию в отдельную страницу вроде выставки), и завести самостоятельный блок Contact вместо почты, спрятанной внутри About.

Также меняется визуальный тон публичного сайта: сейчас он выглядит отчасти "кричаще" (жирные контрасты, крупные элементы), целевое ощущение — аккуратнее и уютнее. Для этого в проект добавлен набор скиллов `better-ui`/`better-layout`/`better-typography`/`better-colors`/`better-accessibility` (`.claude/skills/`, источник — https://github.com/jakubkrehel/skills) — применяются при вёрстке/правке публичного CSS.

## Цели

- Владелец в студии включает/выключает каждую секцию отдельным тумблером (не чекбоксом) и меняет порядок секций перетаскиванием.
- По умолчанию порядок: **Works → Exhibitions → About → Contact → Shop**. Все пять включены.
- Хедер (hero) всегда виден, не входит в список переключаемых/перетаскиваемых блоков, редактируется отдельно от секции About.
- Серии становятся частью Works: на главной каждая серия — одна карточка со случайно выбранной работой из серии (обложка), клик ведёт на отдельную страницу серии (по аналогии с `exhibition.html`), где уже показывается полноценная серия (как сейчас аккордеон/слайд-шоу). Работы без серии остаются отдельными карточками на той же сетке Works, открывающими существующий просмотрщик (viewer), а не отдельную страницу.
- Contact — новый самостоятельный блок, отвязанный от About: почта (перенесена из About) + свободный список ссылок (подпись + URL), добавляемых в студии. При добавлении ссылки студия сама подставляет иконку соцсети по домену, если он распознан.
- Публичный CSS/вёрстка получают более спокойный, собранный визуальный характер — с опорой на `better-ui`/`better-layout`/`better-typography`/`better-colors`.

## Не цели / не делаем сейчас

- Не делаем drag-n-drop произвольных вложенных блоков внутри секций — переставляются только сами пять секций верхнего уровня.
- Не делаем конструктор хедера с несколькими вариантами раскладки — один фиксированный вид хедера, меняется только текст и, опционально, картинка (уже есть через `heroWorkId`).
- Не добавляем форму обратной связи, телефон как отдельное типизированное поле и т.п. в Contact — только email + произвольные "подпись + URL" ссылки.
- Не меняем способ публикации каталога (черновик/публикация остаются как есть), только состав и порядок секций — часть той же модели черновик/публикация.
- Полный редизайн публичного CSS не входит в объём: только точечная правка плотности/контраста/типографики согласно `better-*` скиллам, не переработка композиции секций, которая не затронута этой задачей.

## Анти-цели (что будет провалом, даже если технически работает)

- Выключение секции даже временно ломает ссылки на неё (`#series`, `#shop` и т.п.) где-то ещё на сайте (например, кнопка в Shop "review-request" ведёт на `#shop`) — такие ссылки должны адаптироваться к текущему состоянию.
- Серии, выключенные из Works, остаются доступны по прямой ссылке на страницу серии (это ок и ожидаемо — так же работает с архивными/неопубликованными сущностями уже сейчас: только опубликованные данные видимы). Провалом будет обратное: если выключение секции Works в лэйауте случайно удаляет данные серий из каталога или ломает прямые ссылки на уже опубликованные страницы серий при включённом Works.
- Тумблер должен быть визуально и семантически тумблером (`role="switch"`/аналогичная доступная реализация), а не перекрашенным чекбоксом.

## Ограничения

- Стек остаётся тем же: ванильный HTML/CSS/JS на паблике, Node.js/Express + Better Auth + SQLite в студии, без фреймворков и сборщиков на паблике.
- Модель данных и валидация в `admin/src/catalogue-model.mjs` должны остаться в том же стиле (строгая валидация всех новых полей, лимиты длины/количества, как для существующих).
- Черновик/публикация, архивация, существующие тосты и паттерны студии (единая модалка добавления, подтверждения перед необратимыми действиями) используются и для новых блоков — не изобретаем параллельный UX.
- i18n: все новые видимые тексты (подписи Contact-ссылок, лейблы) проходят через существующий `js/i18n.js` там, где это статические UI-подписи; пользовательский контент (сам текст ссылки, email, короткий текст хедера) хранится как `{en,ru,es}` как остальной переводимый контент каталога.
- Существующие тесты (`tests/public-copy.test.mjs`, `admin/test`) не должны сломаться; для новой логики (валидация layout/contact, рендер Works-карточек, страница серии) нужны новые тесты по той же схеме, что и для последних фиксов (см. `8f24ed0 Fix studio render crash and cover request views with regression tests` как образец объёма тестов на фичу).

## Решённое в обсуждении

- **Layout-вкладка в студии:** отдельная новая вкладка. На ней — управление блоком hero (независимые короткие поля) и ниже список из пяти секций (Works/Exhibitions/About/Contact/Shop), перетаскиваемых (как уже умеет SortableJS в других местах студии) с тумблером вкл/выкл у каждой.
- **Hero/header:** полностью независим от About. Поля — только короткий вступительный текст (`{en,ru,es}`), без поля "роль". Эйбрау-префикс "01 /" и кнопка "View the series" убираются полностью. Картинка хедера остаётся как сейчас — через `heroWorkId` (переключатель "Работа на главной" уже есть в студии, не меняется).
  - **Моё решение (минорное):** имя автора в хедере — общее поле с About (`about.name`), не дублируется отдельным полем, так как это один и тот же человек/бренд и отдельного запроса на дублирование имени не было.
- **Works = Series + standalone works:** серия на главной — одна карточка, обложка — случайно выбранная работа серии. Клик по карточке серии → отдельная страница серии (новый `series.html?id=...`, по образцу `exhibition.html`), на ней — то, что сейчас рендерится при раскрытом аккордеоне (statement, слайд-шоу всех работ серии). Работы без серии — карточки на той же сетке Works, клик открывает текущий `viewer` (модалку), как для карточек сейчас работает открытие работы.
  - **Моё решение (минорное):** "случайно выбираемая" обложка — выбирается на клиенте при каждой отрисовке страницы (как сейчас работает `heroWorkId` рендер), а не фиксируется при публикации. Если нужно фиксировать обложку на время сессии/вкладки, это можно уточнить позже — не блокирует план.
- **Порядок карточек в сетке Works:** не вычисляется автоматически (не "сначала серии, потом одиночные работы", не по году) — это самостоятельный перетаскиваемый список в студии, смешивающий карточки серий и карточки одиночных работ в одном ряду. Владелец руками задаёт порядок через drag-n-drop (как список секций на вкладке Layout и другие сортируемые списки студии). Нужно новое поле порядка в модели каталога — единый список записей вида "серия X" / "работа Y" (аналогично тому, как уже хранится порядок `series[].workIds` внутри серии, но на уровне всей сетки Works).
- **Переход на страницу серии:** клик по карточке серии в Works всегда ведёт на отдельную страницу `series.html?id=...` (не разворачивает на месте). Пункт меню «Works»/skip-ссылка ведут на саму сетку Works, а не на конкретную раскрытую серию — автораскрытия по якорю `#series` больше нет.
- **Главное меню при выключенной секции:** пункт меню для выключенной секции полностью пропадает из топбара (а не остаётся неактивным/ведущим в никуда).
- **Contact:** новый блок, модель — `{ email, links: [{ id, label: {en,ru,es}, url }] }`, email переносится из About (убирается из About). Список ссылок добавляется/удаляется/сортируется в студии как остальные списки (works в серии и т.п.). При добавлении ссылки студия определяет соцсеть по домену URL и подставляет соответствующую иконку автоматически.
  - **Моё решение (минорное, нужно подтверждение при ревью билдера, не блокирует план):** первый набор распознаваемых доменов — Instagram, Facebook, X/Twitter, LinkedIn, YouTube, Behance, Pinterest, TikTok, Telegram, WhatsApp, VK, Threads. Нераспознанный домен получает нейтральную иконку "ссылка" (как сейчас `arrow-up-right`/похожая на внешние ссылки выставок).
- **Hero-валидация:** независимые поля хедера (короткий вступительный текст) валидируются теми же примитивами, что и остальной переводимый текст в `catalogue-model.mjs` (`translated()`/`string()`), отдельного пути валидации не заводим.
- **Где считается иконка соцсети Contact-ссылки:** иконка вычисляется по домену URL в студии в момент добавления/сохранения ссылки и сохраняется в модели каталога как ключ (например `icon: 'instagram'`, `icon: 'link'` для нераспознанного домена) — пересчитывается при каждом изменении URL. Публичный сайт не хранит и не пересчитывает таблицу доменов, а просто отображает SVG-символ по сохранённому ключу (по аналогии с уже существующими `<symbol>` в `index.html`), чтобы домен-таблица соцсетей жила в одном месте (студия), а не дублировалась в паблике.
- **Тумблеры:** переключатель видимости секции — визуальный/семантический тумблер, не чекбокс.
- **Порядок и видимость по умолчанию:** Works, Exhibitions, About, Contact, Shop — все включены, в этом порядке, если в данных ещё нет сохранённого layout (миграция для существующих опубликованных каталогов).
- **Визуальный тон:** просьба "аккуратнее и уютнее" относится только к публичному сайту, не к студии. Скиллы `better-ui`/`better-layout`/`better-typography`/`better-colors`/`better-accessibility` установлены в `.claude/skills/` и применяются при правке публичного CSS/вёрстки в рамках этой задачи.

## Что остаётся на усмотрение билдера

- Точная форма хранения `layout` в каталоге (например `layout: [{id, enabled}]` в порядке массива) — лишь бы валидировалась так же строго, как остальные поля `catalogue-model.mjs`, и поддерживала миграцию старых опубликованных каталогов без `layout`.
- Технические детали страницы `series.html` (переиспользование кода `exhibition.js`/`main.js` рендера серии максимально, без дублирования логики слайд-шоу).
- Конкретные классы/токены CSS при приведении плотности/типографики к `better-*` рекомендациям — сохраняя текущие шрифты (Fraunces/Outfit) и палитру, просто смягчая контраст/масштаб там, где скилл это рекомендует.
- Набор распознаваемых доменов соцсетей для автоиконок Contact (стартовый список — моё решение выше, можно расширить/сузить при реализации).
- Обновление `js/i18n.js` под новые статические подписи (например лейбл вкладки Layout в студии, если он на английском интерфейсе студии, и т.п. — студийный интерфейс сейчас на русском, см. `admin/README.md`, статические подписи студии не обязаны идти через публичный i18n).
